# 文档写法

范围：README、skill 正文、代码注释、提交正文、说明性文字。仓库不设 docs/，要沉淀的规范写进 skill。

## 语言

- 简体中文；路径、命令、标识符、专有名词保持原文。
- 术语首次出现补英文：持久化（persistence）；之后只用一种写法。
- 中文与英文、数字之间加一个空格。
- 中文标点用全角；代码与命令内保持半角。
- 强调用「」；引述用户原话用中文双引号。

## 语法

- 规则用祈使句：必须……／禁止……／允许……。
- 事实用陈述句，一句一义，单句 ≤40 字。
- 每条规则附一句「理由：……」，只写一句。
- 不写"我们""我认为"；规则不依赖作者是谁。
- 不用模糊词：可能、大概、尽量、建议、适当、若干。要么定成规则，要么删。
- 不用比喻、排比、设问，不用连续感叹号。

## 禁写

| 禁止 | 理由 |
| --- | --- |
| 赋能、闭环、抓手、生态、一站式 | 空词 |
| 极致、丝滑、强大、优雅、革命性 | 营销词，无法验收 |
| "简单来说""众所周知" | 读者不需要被安抚 |
| "未来可能支持……" | 推测会过期 |
| 复制代码超过 15 行 | 必然与代码脱节 |
| 截图代替文字说明 | 不可检索 |
| 无编号或日期的 TODO | 无人认领 |

## 结构

- 文档只有一个 H1；正文从 H2 起，不跳级。
- 每节首句给结论。
- 表格用于阈值、清单、对照；列表层级 ≤2。
- skill ≤80 行，README ≤40 行；超了拆或删。
- 注释解释"为什么"，不复述代码。
- TODO 必须带编号或日期：`TODO(#12)`、`TODO(2027-01-01)`。

## 何时写

- 行为或接口变了，同一提交内更新对应说明。
- 说明与代码冲突，以代码为准并当天改说明。
- 不写会过期又不落地的内容；要落地就变成规则或 skill。
