# UI 规则

这是笔记应用：用户在编辑区待的时间占九成以上。所以第一条原则是给内容让路，而不是让截图好看。

## 立场

- 内容优先：装饰性的东西（渐变、插图、图标墙）只在不妨碍阅读时出现。
- 克制：一个界面最多一个强调元素，背景最多两级层次；强调出现两次，就没有强调可言。
- 桌面原生：全部操作都能用键盘完成，命中区域不小于 28×28，鼠标精度比触摸高，但没有必要更小。
- 中文优先：字体、行高、标点按中文样张验收，英文样张会掩盖中文字距问题。

## 禁止的设计

| 禁止 | 原因 |
| --- | --- |
| 紫蓝渐变、发光边框、霓虹描边 | 与笔记内容争焦点，且很快显得过时 |
| 玻璃拟态、大面积背景模糊 | 降低文字对比度，长时间阅读累眼 |
| 营销式首屏（大标题＋副标题＋大按钮） | 每次打开都要多点一次才能写字 |
| 卡片网格＋16px 以上圆角 | 卡片切碎阅读流，圆角越大内容越显轻 |
| emoji 当图标 | 跨系统渲染不一致，与线性图标混用很乱 |
| 模态套模态 | 用户会忘记自己在哪一层，Esc 该关哪个也不清楚 |
| 深色模式纯黑 #000 | 白字对比过强，长时间阅读刺眼 |
| 旋转、弹跳、超过 200ms 的过渡 | 每次操作都要等动画，累积起来很烦 |
| 自绘标题栏 | 与系统窗口按钮打架，还要自己处理缩放与吸附 |

## 令牌

颜色、间距、字号、圆角一律从主题模块取，界面代码里不写字面值——否则改一次配色要全仓库搜索。

- 间距：4 的倍数，只用 4／8／12／16／24／32／48。
- 圆角：控件 4，容器 8，浮层 12。
- 字号：12／13／14／15／20；正文 15、行高 1.65；字重只用 400／500／600。
- 字体：`Segoe UI Variable Text`，中文回退 `Microsoft YaHei UI`，等宽用 `Cascadia Mono`。
- 颜色：双主题同名语义令牌——surface-0/1/2、border、text-primary/secondary/disabled、accent、danger、warn、success；正文对比度 ≥4.5:1。
- 动效：悬停 120ms、面板 160ms、浮层 200ms，ease-out；系统开启"减少动态效果"时全部瞬时。
- 尺寸：列表项 40／32，图标 16／20，状态栏 28，输入框与按钮 32。

色值在首个界面定稿时写入本节，在那之前不要自己挑颜色。

## 布局

三栏：导航 240 / 列表 320 / 编辑区自适应；窗口窄于 1100 时合并为两级导航。最小窗口 900×600，窗口尺寸、位置、分栏宽度要记住——每次打开都重新拉宽很烦。

编辑区最大行宽 720，超出居中；一行太长会让眼睛换行困难。每个方向最多一个滚动条，嵌套滚动最容易让人迷失。

## 交互

- 快捷键集中定义，界面里不散落硬编码。
- 破坏性操作首选可撤销：删除笔记后给 5 秒撤销条，比删除前弹确认框更顺手。
- 自动保存：停止输入 800ms 后触发，状态栏显示「已保存」「保存中」「保存失败」，用户需要知道数据到底存了没有。
- 异步操作必须有进行中反馈；失败要给原因和重试入口，而不是只弹一句"出错了"。

## 四态

每个视图都要覆盖：空（一句说明＋一个主操作）、加载（首次扫描工作区给进度，不转纯圈超过 1 秒）、错误（发生了什么＋怎么办）、部分失败（列出失败项，其余照常可用）。

## 文案

动词开头：写「新建笔记」，不写「新建」；按钮文案与结果一致，写「删除」不写「确定」。错误信息要回答问题：「无法写入笔记：磁盘已满。清理空间后重试」。

不用感叹号、卖萌词和"请输入"这类空话。术语与领域词表一致：笔记、标签、工作区、回收站。文案集中在 `crates/ui/src/strings.rs`，分散在视图里以后没法统一改。

## 验收

界面改动附四项：浅色截图、深色截图、空态截图、键盘操作路径说明。缺一项不算完成，因为"看起来没问题"和"用起来没问题"是两件事。
