# 文档写法

## 文档是事实，不是日志

文档回答"现在是什么"和"为什么这样"。某年某月某日决定了什么、改过几次、谁改的，属于 git 历史；写进文档就会腐烂，读者要花时间分辨哪条还成立。

所以文档里不出现日期、状态、版本号、变更记录、作者、TODO、未实现的计划、推测。过时的文档直接删，git 留底。

例外有两个：`docs/roadmap/` 允许列还没做的事，只写未完成的，完成即删；`docs/design/` 记录已定的决策与规范，只写当前结论，不写讨论过程、日期与状态历史。

## 为什么禁口语

口语在对话里没问题，写进文档有两个问题：同一件事出现两种说法（"弄一下"和"处理"），以及情绪词让规则不可执行。文档面向的是未来读它的人或模型，标准写法能让对方一眼判断该做什么。

禁用词：语气词与口头禅（吧、呢、啊、其实、反正、说白了、搞、弄、整、差不多）；网络流行语；模糊词（可能、尽量、基本、通常、一些、稍微）；人称（我、我们、你、大家）；情绪强调（非常、显然、务必、一定要注意）；相对时间（目前、暂时、后续、将来、最新）；营销词（赋能、闭环、生态、极致、丝滑、强大、优雅）。

## 只写四种句子

规则（必须／禁止／允许）、定义（X 是 Y）、事实（现在时陈述）、引用（见某文档某节）。无主语句、问句、感叹句、粗体强调、emoji 都不属于这四类。

标点用全角，中文与英文数字之间加空格，强调用「」。

## 结构与长度

一个 H1，层级不超过 3 层，一节不超过 12 条，能用表格就不用长段落。文档越长越没人读完，所以 skill 的正文保持在一次能读完的长度，细节放进 references/。

## 引用要克制

引用会漂移：文档一改，所有引用点都要跟着改。同一文档内的规则不互相引用；跨文档只写「文档名 + 小节标题」，全文不超过 3 处；禁止「见上文」「如下」，因为文档会被编辑，位置会变。

一条规则只在一处定义，其他地方引用它的名字。
