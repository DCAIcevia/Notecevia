# 项目规则

## 开工

动手前输出四行：任务与完成条件、计划读的文件（≤5）、验证命令、可逆假设。

读取只取任务点名的文件。禁止 `target/`、生成物、日志、全量 `git log`、递归列目录、三方源码。三方 API 查 docs.rs。

预算：读 5 个文件、检索 3 次、列目录 1 次、单次 200 行。超出即停，说明已确认与仍缺，提一个问题或给一个假设。

必问：产品行为、数据格式、接口、依赖、范围、视觉方向。做错要回滚数据或重写两个以上模块，必须先问。

停止：同一问题两次验证失败、需要必问决策、规则冲突、预算耗尽且无假设。停止只报事实与选项。

汇报四段：改动、验证、风险、后续。

禁止：未验证称完成、顺手重构或格式化、为将来加抽象、动无关问题、编造路径与版本号。

## 文档

文档只写当前事实与依据。时间、演变、状态、版本、作者一律不写。历史只存在于 git 与任务系统。

禁止：日期与时刻、变更记录、决策流水、状态与版本元信息、废弃标注（直接删）、TODO、未实现功能与计划、推测。

语体：简体中文。只用四种句式——规则（必须／禁止／允许）、定义（X 是 Y）、事实（现在时）、引用（见某文档某节）。

禁用词：语气词与口头禅（吧、呢、啊、其实、反正、说白了、搞、弄、整、差不多）；网络流行语；模糊词（可能、也许、大概、尽量、基本、通常、一些、稍微）；人称（我、我们、你、大家）；情绪强调（非常、显然、务必、一定要注意）；相对时间（目前、现在、暂时、后续、将来、最新）；营销词（赋能、闭环、生态、极致、丝滑、强大、优雅）。

禁用形式：无主语句、问句、感叹句、粗体强调、emoji。标点用全角，中文与英文数字之间加空格，引号用「」。

结构：一个 H1，层级 ≤3，一节 ≤12 条，表格优先，列表层级 ≤2。

长度：skill ≤80 行，README ≤40 行，注释 ≤3 行。

引用：允许但克制。同一文档内规则不互引；跨文档引用只写「文档名 + 小节标题」，全文不超过 3 处；禁止「见上文」「如下」。

单一事实源：一条规则只在一处定义。

## 代码

分层：core 禁 IO、时钟、随机、UI 类型；ui 不依赖 store；越界违规。

错误：库内 `thiserror`；边界 `anyhow` + `context`；运行时禁 `unwrap`／`expect`；`panic!` 只用于违反不变式。

命名：词表 Note／Tag／Workspace／Trash；布尔 `is_`／`has_`；禁 `utils`、`helpers`、`common`。

规模：单文件 ≤400 行，单函数 ≤50 行。

测试：core 公开函数至少一例；store 临时目录集成测试，覆盖原子写、路径逃逸、未知字段保留、回收站；修复带回归测试。

门禁：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`，三条全绿。

性能：冷启动 ≤500ms；1 万条列表 ≤1.5s；1 万条搜索 ≤100ms；输入延迟 ≤16ms；空闲内存 ≤200MB。

依赖：标准库优先；维护活跃或事实标准；MIT／Apache-2.0 兼容；先说用途与风险；直接依赖上限 40。

## Skill

新增前确认现有 skill 是否已覆盖。命名 kebab-case，目录名与 `name` 一致。

`description` ≤60 字，写清何时加载与内容。<正文>只写可执行规则，单文件 ≤80 行。

新增、改名、删除必须同次更新 `AGENTS.md` 加载表。

提交类型 `rules`，scope `skills`。
